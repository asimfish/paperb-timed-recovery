## 冻结后真正跑的矩阵

使用上轮180份实际主动第2次检查点里的首轮公开历史，逐一与无故障、首条丢失、持续主执行器失效三种当前条件组合，运行四个控制：保留历史、清空历史、参照保护、当前尝试复核。共180×3×4=2,160；每臂180个稳定条件与360个变化条件，涵盖全部六个有向故障变化。没有按结果筛选病例。

参照保护向首条A命令加预测事件上界门控，仍允许旧支持选择预先安排的重试；它不声称当前尝试已证实故障。当前尝试复核只使用故障无关候选；没有完整候选时执行同一强恢复规则，等交付的初始失败反馈后选择重试。两者同用硬件命令族，但信息与保护守卫不同；候选排序实现明确保存在冻结源码中，并非只加一个计分标签。

| --- | --- | --- | --- | --- |
| 保留历史 | 66 / 114 / 0 | 100 / 260 / 0 | 0 / 14 | 14 |

| 参照保护 | 60 / 120 / 0 | 114 / 246 / 0 | 0 / 0 | 0 |

所有2,160次B连续性TRUE。参照保护在稳定条件相对清空修复3例、损害0例；相对保留历史失去6个通过机会，这六例均没有可准入的保护后计划，回退强规则后时间失败。全部14个变化损害来自旧“首条丢失”支持遇到当前有效首条，并改变原参照。当前尝试复核逐例计分与清空相同，在这个已知无噪声模型里没有新的优势。

这是一次基于已经收费的实际首轮反馈的检查点矩阵，不是新十次曲线。不能把稳定66→60→57外推为真实机器人成功率，也不能证明一般的安全／效用下界。预测参照在本次精确已知动力学下匹配独立原参照；未知模型、噪声、持续现实时间和化学依赖仍需要另外验收。

## 执行与原件

七项源先通过六次原生预检再冻结。NAS上的首次矩阵运行出现四个工作进程均等待I/O，于是保留原冻结源和106个部分目录，单独冻结本地I/O版本：控制、计分、物理XML和名单不变，只把输出迁到本机临时目录并复用已封存的来源哈希。重叠部分的CSV、命令、公开决策和物理效果逐文件字节核对一致。完整新矩阵单独计数，不累加部分重试。

完整原件随后打包持久化到科研工作区的`native_execution_v2.tar.gz`，摘要见[NATIVE_ARCHIVE_RECEIPT.json](NATIVE_ARCHIVE_RECEIPT.json)。科研视频与每帧／源CSV哈希见各视频的PROVENANCE文件。公开仓库提供视频、图和审计摘要，原始矩阵归档留在科研工作区，不是完整公开数据集。

旧SSH转发仍拒绝连接；本轮只读发现同主机`ubuntu-TRX50-AI-TOP`有可用SafeLab场景及正在运行的其他作业。初始GPU资源查询返回驱动／NVML版本不匹配；随后仅对只读查询使用已有570兼容库，确认本机两张RTX5090和剩余显存。该查询不等于作业资源分配或启动验收；本轮没有抢占或新启动Isaac／GPU训练作业。没有安装全局驱动、变更既有资源配置或触碰其他作业。

本轮新VLA权重、DP／RL训练、模型采集请求、真实机器人与化学终点均为0。下一实验应在隔离的SafeLab作业中接入独立捕获／交付／推理／执行／物理效果日志，并让过程在模型推理时持续演化；启动前需确认可用GPU和资源准入。机械组件的保护结果是接口与控制证据。

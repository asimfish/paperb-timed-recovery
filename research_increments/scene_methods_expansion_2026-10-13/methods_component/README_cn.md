# 两个时间窗口通过，并不等于持续时间合同通过

本组件验证接触与稳定释放的联合时间调度，只运行 CPU 上的合成机械延迟区间。它没有新机器人轨迹、PhysX 样本、化学测量或学习更新。A-r7 的 4 校准 + 16 测试矩阵尚未执行；其冻结源没有改动。

完整条件为 **6,912 个参数格点条件 + 256 个固定 seed 合成抽样 + 4 个边界例 = 7,172 条件**。每个旧方法均保留 7,172 分母，包含所有异常和拒绝。这里的 seed 只生成数学输入，不是物理实验 seed；条件计数不能当作机器人 episode 数。

## 数学合同

公开请求接触在 cue 后 D 秒发生，稳定释放在 D + H 秒发生，并要求两个发生区间之差在 H 的容差内。位置指令经公开的固定 FIFO 延迟 q 送达；机械延迟属于给定区间 LA、LB。命令派发时刻为 a、b，源技能要求 a 不早于 4 秒，b − a 不短于给定技能时长。

对一个给定区间盒，三项合同要同时满足：

```text
D − eps <= a + q + LA_lo
a + q + LA_hi <= D + eps
D + H − eps <= b + q + LB_lo
b + q + LB_hi <= D + H + eps
H − eps <= b − a + LB_lo − LA_hi
b − a + LB_hi − LA_lo <= H + eps
```

这只是条件区间可行性。四条校准的经验包络没有统计覆盖保证，不能直接等同真实部署的完整延迟支持集。真实误差可能超出包络；新原生验证仍需独立进行。

## 实际发现

冻结原调度器在联合枚举前先计算独立中点调度的 hold。如果这个中点需要缩短源技能，就提前抛异常；但这不能证明整个时间窗口都不可行。D = 5、H = 17.95、技能最短 18 秒、容差 25 ms、LA = [0.158, 0.162]、LB = [0.118, 0.122] 是一个反例：原调度器误拒绝，但 a = 1161 / 240、b = 5481 / 240 满足三个合同及技能限制。

本组件保留原调度器的代码及全部失败，另写独立候选求解器。候选逐接触格点求出释放格点可行区间，并在该区间选择中点目标附近的最优格点。独立 oracle 枚举所有两个绝对窗口中的格点对，再检查四个机械响应角点、持续时间和最短技能时长。

7,172 条件中数学可行 2,606，候选全部覆盖，与独立完整 oracle 的选择和精确代价 **7,172 / 7,172 一致**。原联合调度器覆盖 2,545，误拒绝 61，没有错误接受。原独立中点方法有 994 条件的两个绝对窗口都通过，但持续时间区间不通过。

| 方法 | 分母 | 满足完整区间合同 | 保留异常 | 明确拒绝 |
|---|---:|---:|---:|---:|
| 旧名义提前补偿 | 7,172 | 409 | 975 | 0 |
| 旧名义 + 公开 FIFO 补偿 | 7,172 | 788 | 981 | 0 |
| 区间中点 | 7,172 | 2,375 | 1,198 | 0 |
| 冻结原联合调度器 | 7,172 | 2,545 | 1,198 | 3,429 |
| 新 CPU 候选联合求解器 | 7,172 | 2,606 | 0 | 4,566 |

这里报告的是合成区间数学验证，表中的通过数量不是机器人成功率。源码在全矩阵执行前冻结；10 个小预检例不计入上述分母。主矩阵完成 299,040 次独立格点对检查，完整可行集合保存在 oracle_pairs.jsonl。

发生区间和确认时间单独记录。合成例说明，替换成第三个样本的确认时刻会把本来通过的发生窗口判为迟到；首样本已经为真的事件仍作为 LEFT_CENSORED，不能给出完整发生括区间。

A-r7 的既定 H = 18 / 18.5 秒、技能最短 17 秒，在 192 个对应合成延迟条件下没有上述误拒。真实新校准尚未得到，因此这里只给充分条件：平均释放延迟减平均接触延迟不超过 H − 最短技能时长 − dt。不能据此宣称任意校准都免疫该问题。

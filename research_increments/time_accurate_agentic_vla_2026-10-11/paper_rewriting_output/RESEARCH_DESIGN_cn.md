## 1. 论文应回答的问题

**能否把化学操作的事件计时、动作完成时限和计算开销共同放入一个可学习的具身决策过程，让 agent 在还有时间时获取信息，在窗口变窄时及时执行，并将多任务专家的经验吸收到一个视觉—语言—动作模型？**

候选英文题目：*Time-Accurate Agentic Policies for Chemical Manipulation*。名称只是工作题目。候选方法称为 time-conditioned agentic VLA，不声明首创。

核心贡献应落在“选择下一项物理动作及是否再花时间获取信息”的联合决策上。GPT 采集、DP、RL、harness、OPD 是实现和训练路线，单纯串接这些方法不足以构成新算法。

## 3. 时间的语义与计量

### 3.1 三类要求

1. **规定持续时间**：例如有效加热开始后持续 τ 秒，允许误差 ε。计量的是有效加热结束事件，而非发出 stop 请求的时刻。
2. **完成截止时间**：触发事件 e 发生后，必须在 5 秒内完成操作后置条件。移动启动、模型回答和工具返回都不能替代物理完成。
3. **允许窗口**：只允许在事件后的 [L,U] 内完成特定操作，同时满足前置条件、依赖及状态/量约束。

这些数字是作者的问题示例，不是未经校准的真实化学配方。实际任务的允许窗口由基准/经审核协议指定。

事件 e 的时间为 t_e，物理完成为 T。持续时间误差为 |(T−t_e)−τ|；窗口超限为 max(L−(T−t_e),0,(T−t_e)−U)。截止任务只计迟到，不能把提前完成当成错误。

### 3.2 事件锚点和独立记录

每个 recipe 指定 anchor：实际开始加热、达到目标温度、完成加料、接触/释放确认等。命令时刻只能在协议明确采用命令锚点时使用。视觉/传感检测误差、时钟误差和停止延迟分别记录，缺失值保留 UNKNOWN。

每次调用记录 image capture、request admission、reasoning start/return、command submit、physical start/end、feedback return 和 cancel/stop end；所有可用事件使用同一单调时钟或明确的同步误差界。检查、等待、排队、重试和恢复期间，化学过程持续推进。

主指标为 `joint_success`：物理任务完成且满足全部适用时间和状态/量约束。另报时限满足率、提前/迟到比例、规定持续时间误差、失败类型、停止尾流和 agent/API/求解开销。未完成任务计失败；完成条件下的误差是附加诊断，不能作为唯一主指标。

## 4. 模型与部署闭环

公共输入 h 包括带采集时间的图像、语言任务、机器人/仪器公开状态、返回的工具结果、事件记录、可用预算和已提交动作前缀。隐藏裁判、未来状态、未返回测量和私有参数不得进入策略。

事件模块给出每个活动操作的 elapsed、remaining window、observation age 和 timing uncertainty。它们使用明确单位，不能用帧数冒充物理秒数。

部署模型有共享视觉—语言表示和两个输出：

- **时间条件动作头**：扩散动作序列 a，条件为图像、指令、公共历史和时间上下文；给出可执行控制和预测完成时间。预测时间用于调度，实际评分仍依据物理记录。
- **计算决策头**：选择直接提交动作、获取新观察、调用 agent 诊断/规划、调用已注册专家或停止。它依据当前信念、剩余时间、工具时延及已有动作，限制调用次数和取消条件。

GPT agent 可在数据阶段编译任务、提出采集/恢复分支并检查返回信息；在部署阶段作为可选高层工具。不能让无限时长的 GPT 回答成为停止加热的唯一路径。

独立 harness 在共同接口上检查前置条件、窗口、物理动作和已有 stop 界，处理提交和撤销。它既围绕数据采集，也围绕训练 rollout 和最后部署。主对照全部共享相同 harness；只有单独的仿真消融允许关闭相应规则。安全停止不等于任务成功，提前停止必须按任务要求计失败。

如果时间条件 DP 只有图像而没有语言条件，结果只能称 timed visuomotor DP。VLA 主结果必须使用实际图像与指令编码，验证不同任务指令改变动作，并记录 backbone、action head、更新参数、预测/执行 horizon 和真实时延。

## 5. Agentic 理论：计算也是消耗物理时间的动作

令 z=(b,h,c,p,B) 包含公开历史诱导的状态信念 b、上下文 h、事件时钟 c、已提交动作前缀 p 和剩余资源 B。元动作 m 是物理执行或有成本的观察/推理。调用耗时 Δ 后，真实过程在当前已提交控制下演化，结果 y 仅在返回后可用。有限时域、无折扣的递推为

`V(z)=max_m E[r(z,m,Δ,y)−λ C(m,Δ)+V(z′)]`，

其中成功、失效或截止终止时后续 V 为 0；所有操作含正时长或消耗有限调用额度。若改用连续时间折扣，必须使用 exp(−βΔ)，不能把不同持续时间当成同一离散步。

`VOC_time(m,z)=Q_m(z)−Q_execute(z)`。直接执行的 Q 也包含必要等待、动作执行与停止延迟。只有其时限可行、公共信息下的预期收益足以抵消成本时才继续调用。精确求解通常不可行，实际计算决策头须用开发数据学习近似，且调度器本身的耗时计入 Δ。

### 5.1 可证明的基本条件，非首创定理

**窗口可行条件。** 设当前事件后时间为 c，下一工具时长最多 d_max。决策器选择等待 w≥0；物理完成余时 D 在所有候选启动时间和可达状态下具有统一区间 [d_lo,d_hi]，覆盖概率至少 1−δ。另有计时误差 |E|≤η。保守要求

`L+η−d_lo ≤ c+d+w ≤ U−η−d_hi`。

工具返回后重新读时钟。要为最坏返回时刻预留可执行计划，充分条件为 `max(c+d_max, L+η−d_lo) ≤ U−η−d_hi`。若满足，返回后取 w=max(0,L+η−d_lo−c_return)，在覆盖事件上物理结束满足窗口；证明直接代入上下界。

这是在统一完成时间界和有界时钟误差下的充分条件。D 若随等待时刻/状态改变，该统一界必须覆盖这些变化。经验分位数不自动给出此类部署保证。该条件不证明抓取成功、约束满足、可被取消或多步骤递归可行。未知 d_max、失效执行器和新的任务不享受该结论。

**旧图像推理可能降低正确率。** 二值过程每个时间步独立翻转概率 h∈[0,1/2)，初始观察正确率 p₀>1/2。物理动作需要一时间步。更强的旧帧解读给出边际分类正确率 p₁，额外耗时 d 步。两者分别在足够宽的窗口内立即执行，准确率为

`P_direct=1/2+(p₀−1/2)(1−2h)`；

`P_reason=1/2+(p₁−1/2)(1−2h)^(d+1)`。

因为每步翻转将偏离 1/2 的置信度乘以 1−2h。只有 `(p₁−1/2)(1−2h)^d > p₀−1/2` 才在忽略其他开销时有益；超出截止后成功率为零。这里 p₁ 指使用全部旧帧证据后的边际正确率，不是未经校准的模型自报置信度。

例如 p₀=0.65、p₁=0.99、h=0.2、d=3 时，direct 为 0.59，reason 为 0.563504。该构造说明提升旧帧识别并不保证提升当前动作；它不是机器人实验。

**时钟的可辨识边界。** 限定为一次不可撤销的物理决策：若决策前两种等概率历史对策略可见输入完全相同，而它们的可行决策集合互不相交，则任何只使用这些输入的随机决策，平均成功率至多 1/2。证明是两个互斥决策集合的概率之和至多 1。当前像素相同并不充分：必须同时排除历史、指令及其他可推断时间信息。允许在决定前取得能区分两种历史的新观察时，该界不适用；对完整交互策略作相同结论，须另证其全部可获得信息均不可区分。该基本信息界解释时钟赛道，不能证明我们的特定网络最优。

## 6. 把作者要求的路线落实到训练阶段

| 阶段 | 具体设计和输出 | 必须验证的作用 |
|---|---|---|
| GPT agentic 采数据 | 受限协议工具、公开观察、GPT 提议动作/恢复分支、共享 harness 执行；保存 RGB/指令/动作及全部事件时刻、失败、拒绝和 costs | 相同采集预算下对比普通脚本/人工示范；收益是否来自更多数据或更广覆盖 |
| 时间条件 DP/VLA 初始化 | 同一视觉—语言编码器、扩散动作头；时间上下文包含事件后 elapsed、slack、观察年龄；动作去噪监督和完成时间诊断头 | 以相同数据和参数量比较无时钟、时钟条件以及外置 timer；完成时间头不是裁判 |
| Offline RL | 固定数据，先学习有限时域/时长感知 V/Q；用 IQL 式优势加权去噪作为首选开发适配；记录支持域与终止 | 对比等数据/更新量 BC 及时间条件 BC；是否改善截止前的可行恢复，防止 Q 外推 |
| Online RL | 在推进物理过程的仿真中对任务专家用 [DPPO](https://arxiv.org/abs/2409.00588) 类扩散链更新；保持动作 head 的扩散定义；公开状态、时钟和 latency profile 与部署一致 | 等实际环境时间、交互量及计算；对比跳过 offline 阶段；不能直接对最终扩散动作写常规 Gaussian PPO ratio |
| 规则 harness | 规则在采集和所有 rollout 中先成立；冻结最终提交、取消、停止和约束版本 | 对比同一个模型加普通 timer/harness；所有方法得到相同停止资源，单独报告 intervention |
| 多任务专家 OPD | 学生访问状态，在同一公共历史/当前模型/剩余时域上请求当前任务专家；再收集学生 rollout；用标签做扩散监督，训练计算决策头 | 对比离线专家轨迹 BC、同覆盖直接恢复数据、单专家、任务 token 单模型与多专家；查询预算、active 参数和实际开销匹配 |
| 单模型部署 | 一个共享 backbone 和动作/dispatch 输出；保留共享外部时钟与 harness；agent 调用可选、额度冻结 | 报告专家保留率、调用频率、时限失败和未见组合；多 head 不自动证明融合收益 |

[Diffusion-QL](https://arxiv.org/abs/2208.06193)提供扩散策略的 offline RL 近邻，可作替代路线；不同时堆叠多个 RL 算法。当前首选 advantage-weighted diffusion 与 DPPO 的兼容性和稳定性仍须开发验证。OPD 指 on-policy distillation，既不是偏好优化 DPO，也不是把任意离线示范改名。

所有专家和学生共享执行接口。专家使用额外私有真值时，作为 privileged ceiling 单独记录，不进入同信息主比较。对 diffusion/flow policy 的蒸馏使用正确的噪声/速度目标，不能假装有可直接计算的最终动作 KL。

专家标签须绑定输入图像采集时间、查询时刻和返回时刻。查询期间学生和过程如何推进必须预先规定；历史快照上的专家动作不能当成返回时当前状态的即时标签。优先在离线重放中复现学生访问状态和工具延迟，或在返回后重新获取当前公开状态再生成标签，同时记账所有查询和重采集。在线训练标签不得进入当次评估策略的过去决策。

## 7. 实验矩阵与验收

### 7.1 任务及数据划分

开发任务包括规定加热/停止持续时间、触发后的 5 秒操作完成、延迟加料窗口和具有并发活动计时的复合操作。先用非危险过程代理或仿真，并区分机械完成与化学过程终点。真实试验的硬件与配方另外冻结，不在本方案中给出未经审核的反应操作参数。

按任务程序/协议实例分组划分数据，不能把同一次过程的视频帧分进训练与测试。测试含未见持续时间、窗口宽度、延迟/抖动分布、事件检测偏差、恢复触发、任务组合和物理停止延迟。训练/开发/确认单位与模型选择规则先冻结。Paper A 的 A/B/C 时钟赛道分别报告，工具权利不同的结果不混排。

### 7.2 最小强对照

1. 同 backbone 普通 VLA/DP；相同模型加事件时钟；相同模型加可靠 timer 和共享 harness。
2. 时间条件模型加 RTC；延迟 profile 训练版本；Logic-VLA 风格时间条件编码/后训练适配。若无法复现，只写未完成对照，不用不相干公开数值替代。
3. GPT 直接工具策略、固定频率 GPT 修正 VLA、基于 slack 的简单阈值调用、时间条件计算决策头；共同观察权限、harness、上限和失败处理。**主要比较对象 B** 是有能力的模块化路由器：使用剩余时间、观察年龄、开发集校准的不确定性、工具时延分布和成本，配合同一动作模型、timer、RTC 和 harness。固定调用/简单阈值仅作诊断，不能作为主要获胜证据。
4. 阶段阶梯 BC→offline RL→online RL，并加入 BC→online RL；实验不能只对最弱 BC 宣称整个长链有效。
5. 同数据覆盖离线专家 BC、同状态单专家 OPD、多专家 OPD、任务 token 单模型；避免恢复覆盖、容量或更多 teacher queries 冒充 OPD 增益。
6. 联合训练动作/计算头与分别训练的两头，在同 backbone、容量、训练覆盖和预算下比较；同时比较学习路由器与 B，区分学习调度、联合训练和模型容量的作用。

若相机连续取帧或跟踪器已运行，基线有权免费或按真实边际成本使用该信息，不能人为把它包装成昂贵观察工具。所有方法计入调度自身耗时、并发已提交动作和返回信息的实际可用时刻。

| 问题 | 主读数 | 必须保留的对照/边界 |
|---|---|---|
| 时间输入是否有用？ | joint_success、持续时间误差、early/late | 当前图像相同、事件历史不同；时钟/帧率赛道不合并 |
| 学习是否超过 timer？ | 同 timer/harness 下 joint_success | 同观察/截止/停止权限，展示原始模型与保护后的结果 |
| agent 何时值得调用？ | 按 slack/latency 分层的收益与成本 | 主要与校准模块化路由器 B 比较；联合与分别训练；固定调用、新观察、旧帧推理作诊断；世界不暂停 |
| RL 各阶段是否需要？ | 按真实交互时间的学习曲线 | 更新量和采集量分别计账，保留 skip-offline/skip-online |
| OPD 是否有独立收益？ | student/expert 保留率、未见组合 SR | 等覆盖、单教师、任务 token、真实 active 参数及 teacher cost |
| 真实停止是否准确？ | 命令到物理终点分布、超时/尾流 | 不把 command stop 当 physical stop；失效和 UNKNOWN 保留 |

主结果建议至少三个训练 seed；评估 episode 数由开发方差和最小有意义差异决定，确认前锁定。单位按独立过程/任务实例进行配对统计和 cluster bootstrap；同视频帧、派生延迟配置或优化重复不当作独立物理重复。报告 task-macro 与 episode-micro 的分母和失败数。

主要统计量预先固定为完整配对队列上的 `joint_success(candidate)−joint_success(B)` 有符号差值及其区间；取消、工具失败和未完成仍在分母中。UNKNOWN 的主处理和敏感性分析先规定，不得确认后按结果删除。OPD 保留率是第二研究问题，不能替代对 B 的主比较。

### 7.4 顺序和停止条件

- **D0 机制校验**：精确二值 belief 模型，验证推理与重新观察在延迟下的不同作用。只检验理论实现。
- **D1 视觉任务 headroom**：在至少两个具有图像、语言指令和物理完成计量的操作家族中，检查共享 timer/harness 的控制及路由器 B。候选为规定持续时间的停止和触发后限时转移。若强基线已饱和，记录负结果；只依据已有协议需求扩展耦合任务，不能降低对照、制造隐蔽状态或任意缩窄窗口来创造收益。
- **D2 采集与 DP**：冻结采集/成本接口，验证 GPT 与脚本数据覆盖及时间条件动作表示。
- **D3 RL**：先证明 offline→online 或直接 online 的开发收益；无收益阶段从主方法删除，记录负结果。
- **D4 agent 与 OPD**：冻结计算决策头、专家同状态标签和资源，测其独立收益及蒸馏保留率。
- **D5 确认与物理校准**：上述开发通过后冻结确认协议，再进行独立测试与可核验停止计量。

当前完成度：D0 的 V1 已完成标准库精确计算和九项本地测试；独立审查发现共用递推不能作为独立 oracle，且输入类型约束不完整。活动 V2 增加独立逐 tick 值递推检查和严格类型约束，十项测试和全网格计算实际退出码均为 0；全部 432 格、2592 个策略读数与原 V1 一致。D1–D5 未完成。432 个确定性参数格中，强制旧帧推理相对直接执行有 180 格成功概率下降、252 格上升。这个比例只描述所选网格，不能估计真实机器人上的发生频率。已知模型最优策略是分析上界；它的选择分别为直接动作 98 格、旧帧推理 125 格、新观察 150 格、先等待 59 格。它不是学成的 agent，也不是新 VLA 性能。原始 [V1 结果](../exact_pilot_results_v1.json) 保留不改；修订 [V2 结果](../exact_pilot_results_v2.json) 和 [执行记录](../EXACT_PILOT_V2_EXECUTION_RECEIPT.json) 独立保存。

旧 NSS 结果属于常规系统识别；不可变模型绑定属于开发工程验证；二者都不能补充为本方法的 VLA 主结果。CT-C1 仍 MAJOR_OPEN。
